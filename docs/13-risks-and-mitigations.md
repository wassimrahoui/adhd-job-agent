# Risks and Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| Adzuna's coverage doesn't include a relevant employer/job (aggregators don't index everything) | User misses jobs a broader search would find | Explicitly accepted for MVP as the cost of ADR-004's decisiveness; the source adapter interface is retained so a second connector can be added post-MVP without a redesign, once Adzuna's real coverage gap is measured rather than assumed |
| Adzuna's free/developer-tier daily quota is exhausted before discovery completes | Fewer jobs found that day | Quota tracked as configuration, backed off gracefully, surfaced as an explicit "discovery unavailable today" state rather than a silent zero-results run (`03-job-sources-and-browser-automation.md`) |
| Adzuna's `description` snippet is truncated and omits detail a full posting would have | AI/user work from an incomplete picture for some jobs | Snippet limitation documented and shown honestly (not hidden); full-page extraction is a documented, explicit post-MVP option, not a silent gap |
| The pinned model (`qwen2.5:14b-instruct-q4_K_M`) underperforms in practice on real Adzuna-shaped jobs despite fitting the hardware budget on paper | Bad or untrustworthy matches shown to user | Verified against the hallucination/evidence test suite with real fixtures before adoption (`14-model-evaluation.md`); a model change is a deliberate, documented, re-verified decision, never automatic; deterministic matching still works with AI marked unavailable |
| The pinned model's real-world VRAM/RAM footprint exceeds the budget once other software is also running | Ollama fails to load the model, or starves other processes on the shared machine | Budget is explicitly a target to measure against on real hardware post-implementation, not just trust vendor figures (`14-model-evaluation.md`, "Verification before trust"); low/queued concurrency (ADR-010) caps peak usage regardless |
| Adzuna changes its response shape/fields without notice | Normalization silently mis-maps fields or breaks | Adapter-level schema checks fail loudly on unexpected shape; treated as an extraction error, not fabricated data, mirroring the general "website changes its HTML" lesson from prototype 1 applied to an API contract instead of a page |
| ATS/browser automation encounters anti-automation measures (CAPTCHA, bot detection) during application prep | Automation stalls | Explicit human-intervention state, no bypass attempted, ever (rule 9 boundary) |
| Ollama or the local model host is down or overloaded | AI analysis unavailable | Honest `AI_UNAVAILABLE` degraded state (ADR-006); deterministic match and manual review still fully functional |
| User's mailbox provider access is revoked or misconfigured | Email monitoring stops working silently | Connection-health surfaced in Settings; failures logged and visible, not silently swallowed |
| Deduplication incorrectly merges two distinct jobs, or fails to merge true duplicates | User sees confusing duplicate listings, or loses evidence from a merged source | Deterministic, documented, tested dedup identity strategy (`03-job-sources-and-browser-automation.md`); both source evidences retained on a correct merge, so a wrong merge is auditable and reversible in principle |
| Evidence verification produces false negatives (rejects true claims) too aggressively, frustrating the user with `UNKNOWN` labels on things that were actually stated | Reduced perceived usefulness | Verification tuned and tested against fixtures with known-correct claims; erring toward `UNKNOWN` over `FACT` is treated as the safer failure mode given rule 5, and is preferred over the alternative risk (false positives shown as fact) |
| Scope creep into autonomous application submission over time (feature pressure) | Violates rule 9, erodes trust and safety guarantees | Rule 9 documented as non-negotiable; API design has no code path for unattended submission (`07-api-design.md`); any future request to add one requires explicitly revisiting and rejecting this ADR set, not a quiet code change |
| Single-user, self-hosted deployment makes the system solely responsible for its own uptime/backups | Data loss if the host fails | Standard Postgres backup practice documented for the deployment (not a novel requirement of this system); out of scope for the application architecture itself beyond not actively working against good backup hygiene |
| Coding agent (OpenCode or a future replacement) fabricates a "done" during implementation, mirroring prototype 1's history | Broken or incomplete features believed to be finished | ADR-002 applied to development: independent test re-run and diff review required before any task is accepted as complete |
| Prompt-injection technique not covered by current tests emerges later | Could theoretically influence AI output text | Layered defense (`08-security-and-prompt-injection.md`) means even a successful injection has no action to trigger and no secret to leak; new injection patterns are added to the adversarial test suite as they're identified, per `09-testing-strategy.md` |
