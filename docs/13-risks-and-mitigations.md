# Risks and Mitigations

| Risk | Impact | Mitigation |
|---|---|---|
| Adzuna's coverage doesn't include a relevant employer/job (aggregators don't index everything) | User misses jobs a broader search would find | Explicitly accepted as the cost of ADR-004's decisiveness; the source adapter interface is retained so a second connector can be added later without a redesign, if that's ever genuinely needed |
| Adzuna's free/developer-tier daily quota is exhausted before a search completes | Fewer jobs found on that search | Quota tracked as configuration, surfaced as an explicit "quota exhausted for today" state rather than a silent zero-results run; since search is a single user-triggered request rather than a background job, there's no retry-queue complexity to reason about (`03-job-sources.md`) |
| Adzuna's `description` snippet is truncated and omits detail a full posting would have | AI/user work from an incomplete picture for some jobs | Snippet limitation documented and shown honestly (not hidden); full-page extraction is explicitly out of scope, not a silent gap |
| The candidate analysis model (`qwen2.5:14b-instruct-q4_K_M`, pending real-hardware benchmark validation — `14-model-evaluation.md`) underperforms in practice on real Adzuna-shaped jobs, or fails to meet the hardware budget once actually benchmarked | Bad or untrustworthy matches shown to user, or the model can't be used at all on Wassim's hardware | Verified against the evidence test suite with real fixtures, and against real VRAM/RAM usage on the target machine, before adoption is finalized (`14-model-evaluation.md`); a model change is a deliberate, documented, re-verified decision, never automatic; deterministic pre-filter results still work with AI marked unavailable |
| The pinned analysis model's real-world VRAM/RAM footprint exceeds the budget once other software is also running | Ollama fails to load the model, or starves other processes on the shared machine | Budget is explicitly a target to measure against on real hardware post-implementation, not just trust vendor figures (`14-model-evaluation.md`); strictly sequential processing (ADR-010) caps peak usage regardless — never more than one request in flight |
| Adzuna's response shape changes over time | Extraction silently breaks or returns bad data | Expected-field checks fail loudly rather than guessing; extraction errors are visible states, not silent bad rows; regression tests added from real observed breakages |
| Ollama or the local model host is down or overloaded | AI analysis unavailable | Honest `AI_UNAVAILABLE` degraded state (ADR-006); deterministic pre-filter result and manual review still fully functional |
| Deduplication incorrectly merges two distinct jobs, or fails to merge true duplicates | User sees confusing duplicate listings, or a merge overwrites the wrong evidence | Deterministic, documented, tested dedup identity strategy (`03-job-sources.md`); the merged row keeps the latest evidence, so a wrong merge is auditable and reversible by re-running the search |
| Evidence verification produces false negatives (rejects true claims) too aggressively, frustrating the user with "Unknown" labels on things that were actually stated | Reduced perceived usefulness | The containment check is tuned and tested against fixtures with known-correct claims; erring toward `UNKNOWN` over a false positive is treated as the safer failure mode |
| Scope creep — a future request to add application submission, browser automation, a scheduler, a queue system, Postgres, or Mem0 | Would violate the core simplicity and "never applies automatically" guarantees and re-introduce a materially larger, out-of-scope surface | There is no code path or data model for any of these to attach to (ADR-005, ADR-008, ADR-010); any future request to add one requires explicitly revisiting and rejecting the relevant ADR, not a quiet code change |
| Single-user, self-hosted deployment makes the system solely responsible for its own uptime/backups | Data loss if the host fails | A single SQLite file is simple to back up (file copy); standard backup practice documented for the deployment, out of scope for the application architecture itself beyond not actively working against good backup hygiene |
| Coding agent fabricates a "done" during implementation | Broken or incomplete features believed to be finished | ADR-002 applied to development: independent test re-run and diff review required before any task is accepted as complete (`15-development-process.md`) |
| Untrusted job text influences AI output text in a minor way (e.g. a job posting phrased unusually) | Could theoretically produce a slightly odd explanation string | Kept in proportion: the model has no tool access and no action to trigger, so the worst case is odd output text, which still has to pass schema validation and the evidence containment check before it's shown; not treated as a security incident requiring a dedicated defense project (`01-architecture-overview.md`, `02-ai-and-matching-architecture.md`) |
